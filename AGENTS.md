# Agent instructions for the personal AnimeStudio fork

## Repository policy
- This is `italonvcc/AnimeStudio`. Develop on focused `codex/<topic>` branches and open PRs against this fork's default branch. Never open PRs or push changes to Escartem/AnimeStudio unless the user explicitly changes this policy.
- Preserve the upstream remote and history. Keep fork-specific changes small and isolated so future upstream improvements can be integrated on a separate branch and regression-checked.
- Inspect Git status before editing; preserve unrelated changes. Stage explicit source paths, never exported game data.

## Responsibilities and current scope
- AnimeStudio owns production extraction, file parsing, dependency resolution, model/animation/material/audio/VFX export, and the GUI/CLI controls for them.
- Keep Genshin asset/source-data research in this repository's `docs/Genshin/`. Exporter changes, their rationale, and Unity import lessons on exported assets also belong here. The [Unity package](https://github.com/italonvcc/com.caladan.shaders) owns shaders, runtime and Editor tools, shader reconstruction evidence, and actionable Unity setup. Link across repositories instead of maintaining duplicate technical accounts.
- Use the current task and the package's [session handoff](https://github.com/italonvcc/com.caladan.shaders/blob/main/Docs/Session-Handoff.md) for active scope and pauses. Do not resume a paused shader or Manekin phase independently. Historical phase descriptions in older documents are evidence, not current authorization.
- Genshin model/character workflows export FBX models, native Unity `.anim` clips when selected, and source Avatar/manifest metadata. Preserve explicit limits and do not imply that source animation, assembly, or gameplay behavior has been validated solely by export.
- Surface implemented game-specific export actions based on the selected game (Genshin first), while retaining shared behavior for other games. Do not present unfinished research as a working exporter.

## Implementation and validation
- Treat the installed game client as read-only. Put offline probes and export evidence in the established local/ignored paths in this repository (such as `artifacts/` and appropriate `docs/Genshin/Export/` evidence), and game assets imported into Unity under that project's `Assets/_Games/Genshin/`. Do not stage generated game data or overwrite accepted regression exports.
- Preserve source/container/path IDs, skeleton/bind pose, animation timing/root motion, event/language identity, and material/shader dependencies. Report missing information instead of guessing names or silently claiming full export.
- Keep parsing in AnimeStudio, conversion in AnimeStudio.Utility, and GUI orchestration in AnimeStudio.GUI. Reuse the same conversion logic in CLI and GUI where possible.
- Canonical Windows build: run `./build.ps1`. Keep one current Release distribution at `dist/net10.0-windows`, containing GUI and CLI launchers with shared `bin/` dependencies. The script builds both from current source, verifies shared binary hashes and the native FBX library, and keeps logs/backups under ignored `artifacts/build-records/`. Do not leave alternate launchable Debug, framework-version, or named-fix builds. Preserve historical evidence and user maps when retiring old outputs. Native libraries are prebuilt; rebuild only for native changes.
- Validate targeted changes with synthetic checks and bounded real asset samples. A successful build does not establish correct humanoid motion, Manekin assembly, semantic audio mapping, or complete VFX behavior.
- Unity exports contain assets and metadata only. Keep the versioned `anime-studio-import.json` beside each FBX and its same-folder recipe (`manifest.json`, character recipe, or `weapon-import.json`); see the [descriptor contract](docs/Genshin/Unity-Import-Descriptor.md). Unity Editor import code and its [usage guide](https://github.com/italonvcc/com.caladan.shaders/blob/main/Docs/AnimeStudio-Import.md) live in `com.caladan.shaders`; do not generate or copy `.cs` files into export folders, including shared `Generic/Editor`. Preserve source and recipe provenance, and validate representative exports with the package importer through the designated live Editor owner.
